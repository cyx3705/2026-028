# page/ —— 单文件加密聊天页

**一个单文件 HTML，发给对方，双击就能用。**
默认页面自己带着桥的源码；也可以生成一个仓库外的预编译单文件发布页。

```
chat.html  ──WebSocket──▶  bridge.exe  ──剪贴板＋键盘──▶  微信
    │                            ▲
    │  内嵌 bridge.cs              └── 剪贴板监听 ◀── 你在微信里 Ctrl+C
    └── 点一下就能生成安装包
```

---

## 文件

| 文件 | 说明 |
|---|---|
| `chat.html` | **最终产物**。发给对方的就是这一个文件 |
| `template.html` | 源码模板（源码、可选 EXE 和构建戳占位符） |
| `build_page.py` | 把桥源码注入模板；`--standalone` 还会把 `bridge.exe` 注入 `../dist/chat-standalone.html` |
| `check_ids.py` | 静态自检：脚本里 `$("x")` 引用的元素必须真的存在 |
| `test_loopback.js` | 密码学验证（抠出页面里的 Crypto 模块跑真 WebCrypto，18/18） |
| `test_receive.js` | 接收路径、确认层和界面状态验证（DOM 桩，145/145） |

重新生成，然后**两个自检都要过**：

```cmd
python build_page.py                  REM 生成仓库内的源码安装页
python build_page.py --standalone     REM 生成仓库外的预编译单文件页（需先 build bridge）
node test_loopback.js          REM 密码学（18/18）
node test_receive.js           REM 接收、确认与界面状态（145/145）
node test_receive.js ..\dist\chat-standalone.html  REM 独立版同等接收测试
python check_ids.py chat.html  REM 元素引用
```

### 预编译单文件发布页

需要减少对方机器上的编译步骤时，先在 Windows 上运行 `../cs/build.bat`，再执行：

```cmd
python build_page.py --standalone
```

脚本会生成 `../dist/chat-standalone.html`。该文件把当前 `bridge.exe` 编码进页面，
页面生成的安装器只释放并启动它，不再调用 `csc.exe`。`dist/` 和 `cs/bridge.exe`
均已加入 `.gitignore`，不会进入仓库；普通的 `chat.html` 仍只包含源码安装路径。

浏览器出于本地程序启动限制，页面会保存一个安装器，最后仍需用户双击一次；
这是单文件 HTML 能保留的最短交互路径。

### 构建戳

每次构建都会注入一行 `时间 · 源码 sha256 前 8 位`；独立版还会带上 EXE 的 sha256 前 8 位，
显示在两个弹窗底部，控制台也打印：

```
2026-09-18 13:40:00 · cs:d0560e9b
```

**"改了没用"先看这行，对不上就是标签页没刷新**——这个坑真踩过，见下。

## 用法

整个交互就是**右上角三个药丸**。

### 发给对方
把 `chat.html` 直接发过去（微信/邮件/任何方式）。

> ⚠️ **对方必须用浏览器直接打开这个文件。**
> 如果是被塞进某个预览器的沙箱 iframe（地址栏是 `blob:`），
> 文件选择器和下载都会被安全策略禁掉，报
> `SecurityError: Sandboxed documents aren't allowed to show a file picker.`
> 用 Edge 直接打开 `file:///...\chat.html` 就没这个限制。

本地调试服务器（例如 `http://127.0.0.1:8000/`）也可以直接打开页面；回环地址的页面会把
WebSocket 自动指向本机桥的 `8765` 端口。非回环 HTTP/HTTPS 部署则需要由同源服务器代理 `/ws`。

### ① 装桥 —— 「桥」药丸

页面顶部会有一条**大横幅**：`还没装桥 —— 装好后页面会自动连上`。
点开「桥」药丸有详细说明和四个按钮：

| 按钮 | 走什么路 | 什么时候用 |
|---|---|---|
| **⬇ 快速下载** | 浏览器下载管道 | 默认。文件直接出现在 Edge 下载栏，点一次文件即可运行；若提示有害先点「保留」 |
| **选择保存位置** | File System Access API 的「另存为」 | 需要指定目录时使用；保存后在所选目录双击 |
| **📋 手动保存（万能）** | 纯文本框 + 剪贴板 | 上面那条失败时。不下载、不调任何权限 API，**沙箱里也成立** |
| **📤 发送测试消息** | 走桥发一条明文 | 排查"发不出去"是断在哪一段 |

快速下载后，直接点 Edge 下载栏里的 `install-bridge.bat` 一次即可运行；
选择保存位置时，在刚选的目录双击运行。脚本会自己释放 `bridge.cs` →
用系统自带的 C# 编译器编译 → 启动。Windows 可能提示"已保护你的电脑"，
点 **更多信息 → 仍要运行**。

安装脚本启动前会检查已有 `bridge.exe` 进程和 `8765` 端口；发现旧桥时显示 PID/路径并结束安装，
不会覆盖被旧进程锁定的 `bridge.exe`。桥自身也有单实例和端口检查，重复启动会打印现有进程后退出。

**页面会自动连上，不用刷新**（桥连不上时页面无限重试，退避封顶 8 秒）。

### ② 点「密钥」→ 交换公钥

点一下会打开页面内确认框。确认框展示本机指纹、当前微信窗口中获得焦点的会话，
以及桥在线/离线路径；确认前不会发送或写入剪贴板。绑定会话只控制读取，
**不改变发送目标**。

确认后才执行实际动作：

- 桥已连接 → 公钥作为一条微信消息发出去，并显示桥的回执
- 桥在线但 WebSocket 发送失败 → 复制到剪贴板并明确提示手动粘贴
- 桥没连上 → 复制到剪贴板，去微信当前焦点会话手动粘贴
- Edge 文件页拒绝剪贴板权限 → 显示错误和可选择复制的公钥文本框

每次真正发送或复制都要重新确认；取消、Escape 或点击遮罩不会改变状态。

**双方各点一次**，收到对方公钥后自动协商出会话密钥，药丸变绿。

> ⚠️ **发出自己的公钥不会让你变绿。** 药丸要等**对方的**公钥进来才变色。
> 点完之后弹窗里会显示「已发出自己的公钥 —— 正在等对方的公钥进来」，
> 说的就是这件事。真踩过：用户把自己发出去的那串 `E2E1-K.…` 当成对方的，
> 纳闷为什么没配置上。

> 公钥长这样：`E2E1-K.BJzaNTykpvxBrAbnoVyafw3bxxMfjzdnGxHIFRq8lCY7IK3dW…`
> 在微信里看着就是一串乱码。**私钥永远不出本机。**

### 重置密钥

「重置密钥」同样先确认，并显示当前指纹。确认后旧配对立即失效、对方公钥清空、
输入框重新禁用，页面生成新身份；对方需要重新交换公钥。取消会保留当前会话和指纹。

### 📥 手动收下 —— 桥那条链断了也能接上

「密钥」弹窗下半部分有一个粘贴框：把对面发来的那条 `E2E1-K.…` **整条粘进去点「收下」**，
走的是**跟桥推过来完全相同的接收路径**（`handleIncoming`）。
旁边还有「从剪贴板读一次」，剪贴板里明明有、桥却没推过来时用。

**为什么必须有这个入口**：页面的入站口只有 `Bridge.onText`，
必须"桥在跑 + 页面连着 + 剪贴板变化被监听到"三件事同时成立。
任何一件不成立，对面的公钥就进不来——而在加这个框之前，
页面上**连个能粘贴的地方都没有**，只能干看着药丸一直是黄的。

粘贴时会自动清掉换行和空格，所以从微信或记事本复制过来的多行内容也能收。

### 一次收多条：**自动**（推荐）或手动

**自动**：点「密钥」弹窗里的 **「📥 拉取最近消息（手动）」** —— 桥替你拖选+复制，
详见下面「自动拉取」一节。旁边的 **「收到消息自动拉取」** 勾选框打开后，
**微信因新消息自己切到前台**时桥会自己拉一次，不用你点。

**手动**：你自己在微信里拖选若干条，按一次 `Ctrl+C`。
两条路最后都汇到同一处 —— 页面能处理**整块多行文本**：

```
这是一条没加密的普通消息          -> 原样显示成一条气泡
我: E2E1-K.BJzaNTyk…              -> 摘出公钥，协商会话密钥
张三: E2E1-M.AAAAAAAA…            -> 解密，显示明文
```

多选复制常带「发送者: 」前缀，页面会从信封起点截断再处理。

#### ✅ 自动拉取：**做得到**

面板里有 **「📥 拉取最近消息（手动）」** 和 **「收到消息自动拉取」** 开关。桥会：

1. 把微信切到前台（四道安全闸：前台、已登录、拖拽起终点像素属于微信）
2. 在**右侧头像列从下往上拖一个细长方形** —— 这一步就是在微信里"选择"消息
3. 按 `Ctrl+C`
4. 从剪贴板读回来，页面拆成一条条处理：中文原样显示、`E2E1-K.…` 收下公钥、`E2E1-M.…` 解密

微信把选中的消息导成纯文本时，格式是这样的（实测）：

```
Pinavia
2026年09月18日 17:17
E2E1-K.BDSEQpqu…
（空行）
Pinavia
2026年09月18日 17:18
123123
```

`parseWeChatDump()` 剥掉发送者和时间戳取出正文。

#### 自动拉取怎么触发的

**微信 4.x 收到消息不走 Windows 通知中心，也不弹 toast** —— 实测全程没有新建任何窗口，
它就是直接把自己的主窗口激活到前台。所以桥挂的信号是 `EVENT_SYSTEM_FOREGROUND`
打在自己的窗口上（见 `cs/README.md`）。

这带来一个好处：自动拉取**不额外抢焦点** —— 微信已经先抢了。
另外拉完桥会把三样东西还给你：

| 还什么 | 怎么还 |
| --- | --- |
| 光标 | `GetCursorPos` 存一份，`finally` 里放回原处 |
| 前台窗口 | 拉完把用户原来那个窗口 `SetForegroundWindow` 回去 |
| 剪贴板 | 自动拉取先读原内容，拉完写回去（只在我们放进去的东西还在时才写） |

#### 增量：只处理"新的那几条"

微信不给增量 —— 每次拉到的都是**当前看得见的一整屏**，相邻两次大面积重叠。
整屏照单全收的话，每来一条新消息就会把屏幕上所有旧消息重新显示一遍
（密文那条靠 AES-GCM 计数器挡得住，中文那条挡不住）。

所以 `onlyNewMessages()` 先看整屏是不是都见过（比如往上滚了一屏），
否则找上一次的**后缀**和这一次的**前缀**的最长重叠，重叠之后才算新的。
没新的就不说话；自动拉取整屏一个字没变时直接静默返回。

#### 坐标怎么算（这里踩过坑）

**不按窗口比例算。** 左侧图标栏和会话列表是**固定像素宽**（约 390px），
按比例在窄窗口下会掉进会话列表里 —— 窗口宽 800 时 `0.40 × 800 = 320px`，已经是会话列表了。

改成从**右边缘/下边缘算固定内缩**：

```
x 外 = 窗口右边缘 - 30      起点，落在头像右缘
x 内 = 窗口右边缘 - 70      终点，落在气泡右缘
yBot = 窗口下边缘 - 110     起点：输入框正上方，就是"最下面"
yTop = yBot - 300           终点：只往上拉 300px
```

**为什么从最下面往上拉一小段、而不是拉到顶**：早先是从上边缘 +70 一直拉到下边缘，
等于顶着标题栏拖 —— **微信会自动把会话列表往上翻很久以前的消息**。后果有两个：
每次拉到的都是不同的一屏（同一套代码一会儿 866 字符一会儿 1320 字符），
而且把用户正在看的对话位置也带跑了。

改成贴着底部往上拉一段之后就稳了。实测（连拉两次不重置，看第一条是不是同一个）：

| 高度 | 条数 | 两次是否一致 |
| --- | --- | --- |
| 300 | 4 | ✅ 完全一样 |
| 420 | 6 | ✅ 完全一样 |
| 560 | 7 | ✅ 完全一样 |

取最小的 **300**：反正页面只处理最近 5 条，信息越少越不容易出事。

**为什么是"细长方形"而不是一条线**：拖一条零宽度的竖线，微信**根本不选中任何东西**，
而失败是静默的 —— 剪贴板里还留着上一次的内容，于是"拉取成功"其实是读到了旧剪贴板。
实测：竖线两次剪贴板序号都没变，细长方形每次都变。详见 `cs/README.md` 的对比表。


窗口**移动**本来就不影响：每次都重新 `GetWindowRect`，`SetCursorPos` 用的是绝对屏幕坐标
（实测窗口在 `(-2471, 292)` 这种负坐标的第二显示器上也照常工作）。

输入框高度会随草稿行数变，所以底部内缩有兜底：万一拖进了输入框（把草稿选中了），
结果里不会有"年月日"那行，桥会自动加大内缩重试。

#### 自动拉取的限制

- 只拉**当前对话里看得见**的消息（滚出屏幕的拉不到）
- 只处理解析出来的**最近 5 条**
- 拉取会**切走焦点并占用剪贴板**，所以做成按钮触发，不是后台偷偷跑
- 拉取用的那一下 `Ctrl+C` 也会被剪贴板监听线程捕获，所以页面在拉取期间
  **屏蔽剪贴板推送**（否则每条消息会显示两遍）

#### 走过弯路：三条堵死的路

| 路子 | 结果 |
|---|---|
| **UI Automation 读屏** | ❌ 微信 4.x 是 Qt 5.15 + 自绘渲染。**连无障碍桥都开了也没用**：设上 `SPI_SETSCREENREADER` 并重启微信后重探，整个窗口**仍然只暴露 1 个元素**（就是那块自绘画布 `MMUIRenderSubWindowHW`），说明它压根没实现可访问接口 |
| **`Ctrl+A` 全选消息** | ❌ 8 种挪焦点的办法（`Tab`×1/2、`Shift+Tab`×1–4、`F6`）**外加鼠标点进消息区**，剪贴板全部零变化。微信根本没有"全选消息"这个功能 |
| **截图 OCR** | ❌ 中文没问题，但 **Base64Url 密文 OCR 必然出错**（`l`/`1`/`I`、`O`/`0` 混淆），而 AES-GCM 有一个字符错就整个解密失败 |

#### 顺带修掉的三个桥的缺陷

都是自动拉取逼出来的，全部跟"窗口状态"有关：

1. **`ActivateWeChat()` 只处理最小化，不处理"被收进托盘隐藏"。**
   托盘状态下 `IsIconic` 是 `false`，那句 `ShowWindow(SwRestore)` 就不执行，
   于是切前台永远失败。现在补了 `IsWindowVisible` 检查 + `SW_SHOW`。
   （这个是我自己搞出来的：早先在拖选收尾加了一句 `Esc`，之后窗口就被收进托盘了。已经去掉。）
2. **`FindWeChat()` 依赖 `MainWindowHandle`，而隐藏窗口的这个值是 0** ——
   直接导致"找不到微信"，发送和拉取全废。现在加了慢路径：枚举该进程的所有顶层窗口，
   **优先挑"看起来已登录"的**（尺寸够大 + 有可缩放边框），都不过关才退回"面积最大"。
   之所以不能只按面积挑：微信实测还有一个 `1920x1026` 的辅助 Qt 窗口，
   光比面积会挑到它，然后被判成"停在登录界面"。
3. **拉取会和剪贴板监听打架** —— 见上面"限制"最后一条。

> 公钥长这样：`E2E1-K.BJzaNTykpvxBrAbnoVyafw3bxxMfjzdnGxHIFRq8lCY7IK3dW…`
> 在微信里看着就是一串乱码。**私钥永远不出本机。**

### ③ 「🧪 测试」—— 不用等第二个人

点「测试连接」会**现场生成第二把真 ECDH 密钥**当假对方，走真实的 `setPeerPub` 协商。
之后你发一条消息：

```
你输入一句
  ├─ 用我的发送键加密 → 真发到微信当前对话        （可在面板里关掉）
  ├─ 对方钥匙解开它，校验与原文逐字节一致
  ├─ 用对方的发送键加密回复 → 真发到微信当前对话
  └─ 走正常入站路径解开回复 → 页面出现明文气泡
```

微信里一问一答两条密文，页面上一问一答两条明文——**两个方向都真的过了一遍桥**。

之所以能这么干：密钥按公钥字典序切成两半，所以
**对方的发送键 = 我的接收键**。两把钥匙本来就在这台机器上，
回路用的是真 AES-GCM 和真计数器，**不是模拟**。

### 📥 反向测试：我当接收方

上面那个是"我发出去"，面板下半部分是**反过来**——模拟对方把公钥发过来，
你站在接收端看状态怎么变。三步走的是**真实接收路径**（`handleIncoming`），
不是绕过它直接调 `setPeerPub`。

| 按钮 | 做什么 |
|---|---|
| **🧹 1. 清空对方** | 只清掉对方公钥，保留你自己的身份（指纹不变）→ 药丸变黄、输入框禁用 |
| **📨 2a. 发出对方的公钥（走微信）** | 现场造一把真 ECDH 公钥，作为 `E2E1-K.…` **发到微信当前对话**，你去选中按 Ctrl+C，页面就当成真的收到 |
| **📥 2b. 本机直接收下** | 同上，但不走微信，直接把信封喂进 `handleIncoming` |
| **🙅 3. 收下我自己的公钥** | 喂自己的公钥进去，应该被拒绝 |

**预期看到的状态切换**：

```
清空对方         →  密钥 未就绪（黄）    输入框禁用
收下对方的公钥   →  密钥 已就绪（绿）    输入框启用 + 指纹显示
收下自己的公钥   →  「这是你自己的公钥，忽略」，状态不动
```

## 加密设计

| 环节 | 用什么 |
|---|---|
| 密钥协商 | ECDH **P-256**（WebCrypto 原生，零依赖） |
| 密钥派生 | HKDF-SHA256，salt = 双方公钥按字典序拼接 |
| 双向分离 | 派生 64 字节，按公钥字典序切成两把独立的 AES 密钥 |
| 消息加密 | **AES-256-GCM**，128 位认证标签 |
| nonce | **12 字节单调递增计数器**（不是随机的） |
| 防重放 | 计数器同时进 AAD；小于等于已见最大值的直接丢弃 |

消息格式（Base64Url，无 `+` `/` `=`，粘到哪儿都不会被转义）：

```
公钥交换：  E2E1-K.<base64url(公钥)>
加密消息：  E2E1-M.<base64url(iv || ciphertext || tag)>
```

### 为什么 nonce 不用随机的

AES-GCM 在同一把密钥下**重用 nonce 会直接导致明文和认证密钥泄漏**。
随机 96 位 IV 虽然碰撞概率低，但没必要赌——用计数器是确定性的，永不重复。
`test_loopback.js` 里实测确认严格递增且互不相同。

### 有意没做的（按需求"没那么严谨"）

- **没有 SAS 短认证串**：所以防不住微信**主动**做中间人。
  能防的是被动（存日志、事后翻记录）。详见 [`../DESIGN-E2E.md`](../DESIGN-E2E.md)。
- **没有前向保密**：长期身份密钥，私钥泄漏 = 历史消息可解。
- **长度会泄漏**：密文长度 ≈ 明文长度。

## 真踩过的坑

### 1. "点了没反应" —— 弹窗被渲染到屏幕外

```html
</header>
<div class="pop" id="popBridge">   <!-- 是 header 的【兄弟】，不是子元素 -->
```

`.pop` 用 `position:absolute; top: calc(100% + 6px)`。因为没有已定位的祖先，
`100%` 参照的是**初始包含块（整个视口高度）**，弹窗被放到 `100vh + 6px`——**完全在屏幕外**。

**为什么测试没抓到**：只检查了 `classList.contains("show")`（真的）和
`getBoundingClientRect().width > 0`（有尺寸也是真的）。一个在视口外的元素两个条件都满足。

修法：把 `.pop` 移进 `<header>`。`check_ids.py` 是后来加的静态防线。

> **教训**：测可见性要测"在不在视口里"，不能只测"有没有尺寸"。

### 2. 初次连接失败后不重试

第一版 `Bridge.connect()` 在"**初次连接**就失败"时直接 `return`，没安排重试。
可首次运行**恰恰就是这种情况**——页面先打开，桥还没装。
用户装好桥之后页面死活连不上，必须手动刷新。

修法：改成无限重试（指数退避，封顶 8 秒），桥什么时候起来都能自动接上。

### 3. 改了文件，用户跑的还是旧页面

`.bat` 拦截修好之后用户仍说"点不了"。对时间戳才发现
`chat.html` 修改于 12:50，他下载于 12:09。

**本地 HTML 文件更新后，已打开的标签页不会自动更新。**

修法：构建时注入构建戳（时间 + `bridge.cs` 的 sha256 前 8 位），
显示在两个弹窗底部，控制台也打印。

### 4. 沙箱文档里什么权限 API 都用不了

现象是"另存为不可用"和"下载根本没起来"，一度以为是下载管道的问题。
beacon 拿到了决定性证据：

```
t=load        p=blob:     ← 页面跑在 blob: 文档里，不是 file:
t=picker-error  x=SecurityError | Failed to execute 'showSaveFilePicker' on 'Window':
                  Sandboxed documents aren't allowed to show a file picker.
t=paste-copy-failed  x=NotAllowedError
```

`blob:` + "sandboxed document" 是一对孪生特征：页面不是被浏览器当文件打开的，
而是被塞进了沙箱 iframe。沙箱文档按规定禁止调用文件选择器，下载也一起被禁——
"另存为不可用"和"下载没起来"其实是**同一个原因**。

修法两条：**用 Edge 直接打开文件**，以及加一条不依赖任何浏览器权限的
**「手动保存」（文本框 + 剪贴板）**——选中和复制是浏览器原生行为，
沙箱里、`file://` 下、`http://` 下都成立。

### 5. PowerShell 会吃掉 JSON 参数里的双引号

```powershell
python wsprobe.py '{"type":"status"}'   # 到 Python 手里变成 {type:status}
```

非法 JSON，桥直接丢弃，表现是"桥不回话"。**一度以为桥坏了第二处，其实是探针发的东西不合法。**
修法：JSON 一律在 Python 里用 `json.dumps` 拼（`--send` / `--status`）。

### 6. 复制回来的消息不显示 —— 桥的防回声判断吞掉了

现象：对面回复的密文，在微信里 `Ctrl+C`，页面**什么都不发生**。

桥的日志里能看到线索 —— 你复制的那条消息，桥一声不响：

```
[17:07:46] 发送 -> 微信 (49 字符)   结果: ok
          ← 之后没有任何「剪贴板变化 -> 推给网页」
```

真凶在 `ClipboardWatcher`：

```csharp
if (text == _lastSentText) continue;   // do not echo our own paste
```

只要剪贴板内容跟"桥最后一次粘出去的"相同就**永久**忽略。而那条"对方的回复"
正是测试模式通过桥发到微信的 —— 你复制回来的东西跟桥自己刚粘的一模一样，
于是被当成回声吞了。

真实两端使用时不会撞上（对面的桥没有这条记录），**单机自测必现**。

修法：改成按**剪贴板序号**精确识别"这一次变化是桥自己造成的"，
文本兜底只吞一次。回归测试见 [`../test_clipboard_echo.py`](../test_clipboard_echo.py)。

## 登录态护栏

**踩过的坑**：微信被手机端顶下线、PC 弹着登录二维码时，桥的前台校验照样通过
（同一个 pid、同一个 Qt 窗口类），结果密文被粘进二维码窗口，**桥还报告 `ok`**。

现在发送前有三道闸，任一不过**一个按键都不发**：激活 → 校验前台窗口 → 校验登录态。
详见 [`../cs/README.md`](../cs/README.md)。

## 已知限制

- **⚠️ 粘贴目标取决于微信内部哪个输入框有焦点。**
  如果微信没打开任何对话、或焦点在「搜索」框，密文会粘到奇怪的地方。
  **发送前请确认微信里打开着目标对话。** 这一条桥分辨不了（UIA 读不到微信内部）。
- **多端不隔离**：桥是全局单例后端，多个标签页会互相看到消息。
- **只监听 `127.0.0.1`，无鉴权**：本机自用没问题。
- **公钥不持久化配对**：对方公钥只在当前页面会话里有效，刷新后要重新交换
  （私钥是持久化的，所以你的指纹不变）。
