# page/ —— 单文件加密聊天页

**一个 74 KB 的 HTML 文件，发给对方，双击就能用。**
它自己带着桥的源码，所以对方不需要你先给别的任何东西。

```
chat.html   ──WebSocket──▶  bridge.exe  ──剪贴板＋键盘──▶  微信
    │                            ▲
    │  内嵌 bridge.cs (30 KB)     └── 剪贴板监听 ◀── 你在微信里 Ctrl+C
    └── 点一下就能生成安装包
```

---

## 文件

| 文件 | 说明 |
|---|---|
| `chat.html` | **最终产物**。发给对方的就是这一个文件 |
| `template.html` | 源码模板（含占位符 `__BRIDGE_B64__`） |
| `build_page.py` | 把 `../cs/bridge.cs` 以 base64 注入模板，生成 `chat.html` |
| `test_crypto.py` | 加密端到端测试（两个独立浏览器实例） |
| `test_integration.py` | 全链路测试（网页+加密+桥+微信） |
| `integration-shot.png` | 集成测试时抓的微信截图 |

重新生成：

```cmd
python build_page.py
```

## 用法

整个交互就是**右上角两个药丸，各点一下**。

### 发给对方
把 `chat.html` 直接发过去（微信/邮件/任何方式）。对方双击打开。

### ① 装桥 —— 两个入口，随便点哪个
页面顶部会有一条**大横幅**：`还没装桥 —— 装好后页面会自动连上` + **「⬇ 下载安装桥」**。
右上角的 `桥 未安装` 药丸点开也有同一个按钮。

点下去会弹**「另存为」对话框**，存成 `install-bridge.bat`，然后：

1. 双击运行。Windows 可能提示"已保护你的电脑"，点 **更多信息 → 仍要运行**
2. 它会自己释放 `bridge.cs` → 用系统自带的 C# 编译器编译 → 启动
3. **页面会自动连上，不用刷新** —— 药丸变绿 `桥 已连接`

**全程不下载任何东西，不装 Python / Node / .NET SDK。**

> **为什么用「另存为」而不是直接下载**：Chromium 把 `.bat` / `.cmd` / `.exe` 列为危险类型，
> 走**下载管道**会被挂起成 `未确认 xxx.crdownload`，等用户点下载气泡里的「保留」。
> 而 File System Access API 的 `showSaveFilePicker` **根本不经过下载管道**，
> 所以拿到的就是 `.bat`，不需要改格式、不需要打包 zip。
> 不支持该 API 的浏览器退回普通下载，页面上也会提示去点「保留」。

> 桥不一定要页面托管：`chat.html` 用 `file://` 直接打开就能连 `ws://127.0.0.1:8765/ws`。

### ② 点「密钥」→ 交换公钥
药丸显示 **`密钥 未就绪`**，点一下就是**把公钥发出去**：

- 桥已连接 → 公钥直接作为一条微信消息发出去
- 桥没装 → 公钥复制到剪贴板，去微信粘贴给对面

**双方各点一次**，收到对方公钥后自动协商出会话密钥，药丸变绿。

> 公钥长这样：`E2E1-K.BJzaNTykpvxBrAbnoVyafw3bxxMfjzdnGxHIFRq8lCY7IK3dW…`
> 在微信里看着就是一串乱码。**私钥永远不出本机。**

### ③ 之后
页面里打字 → 自动加密 → 自动进微信。
对方回的密文，在微信里 `Ctrl+C` → 页面自动解密显示。

## 加密设计

| 环节 | 用什么 |
|---|---|
| 密钥协商 | ECDH **P-256**（WebCrypto 原生，零依赖） |
| 密钥派生 | HKDF-SHA256，salt = 双方公钥按字典序拼接 |
| 双向分离 | 派生 64 字节，按公钥字典序切成两把独立的 AES 密钥 |
| 消息加密 | **AES-256-GCM**，128 位认证标签 |
| nonce | **12 字节单调递增计数器**（不是随机的） |
| 防重放 | 计数器同时进 AAD；小于等于已见最大值的直接丢弃 |

消息格式（Base64Url，无 `+` `/` `=`，粘到哪儿都不会被转义）：

```
公钥交换：  E2E1-K.<base64url(公钥)>
加密消息：  E2E1-M.<base64url(iv || ciphertext || tag)>
```

### 为什么 nonce 不用随机的

AES-GCM 在同一把密钥下**重用 nonce 会直接导致明文和认证密钥泄漏**。
随机 96 位 IV 虽然碰撞概率低，但没必要赌——用计数器是确定性的，永不重复。
实测确认严格递增：

```
iv1=000000000000000000000001
iv2=000000000000000000000002
iv3=000000000000000000000003
```

### 有意没做的（按需求"没那么严谨"）

- **没有 SAS 短认证串**：所以防不住微信**主动**做中间人。
  能防的是被动（存日志、事后翻记录）。详见 [`../DESIGN-E2E.md`](../DESIGN-E2E.md)。
- **没有前向保密**：长期身份密钥，私钥泄漏 = 历史消息可解。
- **长度会泄漏**：密文长度 ≈ 明文长度。

| `test_crypto.py` | 密钥协商 / 双向收发 / 篡改被拒 / 重放被拒 / nonce 不重用 | **19 / 19** |
| `test_firstrun.py` | **从零程序状态**：未装提示 → 点密钥复制公钥 → 点桥弹面板 → **面板在视口内** → 生成安装包 → 运行 → 编译 → **页面自动重连** | **14 / 14** |

### 踩坑 1：下载 .bat 被浏览器静默拦截

第一次交付时直接下载 `install-bridge.bat`，用户反馈"点了没用，装不了"。

`test_download.py --headed` 一跑就现原形：

```
[新文件] 未确认 274878.crdownload  48086 字节
[卡住]  <- 正在下载或等待用户确认
```

文件落成 `未确认 xxx.crdownload` —— Chromium 的危险类型拦截，等用户点「保留」。
**headless 测试完全测不出来**（headless 下 `setDownloadBehavior: allow` 绕过了这个弹窗），
只有有头模式才暴露。

修法：改成打包成 `.zip` 分发。

### 踩坑 2：初次连接失败后不重试

第一版 `Bridge.connect()` 在"**初次连接**就失败"时直接 `return`，没安排重试。

可首次运行**恰恰就是这种情况**——页面先打开，桥还没装。结果是：用户装好桥之后，
页面死活连不上，必须手动刷新。`test_firstrun.py` 一跑就暴露了。

修法：改成无限重试（指数退避，封顶 8 秒），桥什么时候起来都能自动接上。

### 踩坑 3：弹窗被渲染到屏幕外，点了"没反应"

用户反馈"点药丸没反应"。代码看起来完全正常 —— 事件绑了、类名也加上了。

真凶是 CSS 定位：

```html
</header>
<div class="pop" id="popBridge">   <!-- 是 header 的【兄弟】，不是子元素 -->
```

`.pop` 用 `position:absolute; top: calc(100% + 6px)`。因为没有已定位的祖先，
`100%` 参照的是**初始包含块（整个视口高度）**，于是弹窗被放到了 `100vh + 6px`
—— **完全在屏幕外**。用户点什么都没反应。

**为什么测试没抓到**：只检查了 `classList.contains("show")`（真的）和
`getBoundingClientRect().width > 0`（有尺寸也是真的）。一个在视口外的元素
两个条件都满足。

修法：把 `.pop` 移进 `<header>`，`100%` 就正确解析成 header 高度了。
测试也补上了**视口内检查**：

```js
rect.top >= 0 && rect.top < window.innerHeight &&
rect.left >= 0 && rect.left + rect.width <= window.innerWidth
```

> **教训**：测可见性要测"在不在视口里"，不能只测"有没有尺寸"。

### 踩坑 4：改了文件，用户跑的还是旧页面

`.bat` 拦截修好之后用户仍说"点不了"。查 Downloads 才发现他下载的是 `bridge.cs`
（旧版按钮的名字），而新版按钮下载的是 `bridge.cs.txt`；再对时间戳，
`chat.html` 修改于 12:50，他下载于 12:09。

**本地 HTML 文件更新后，已打开的标签页不会自动更新。**

修法：构建时注入一个构建戳（时间 + `bridge.cs` 的 sha256 前 8 位），
显示在两个弹窗底部，控制台也打印。以后"改了没用"先看这行，对不上就是没刷新。

## 登录态护栏（踩坑后加的）

**踩过的坑**：微信被手机端顶下线、PC 弹着登录二维码时，桥的前台校验照样通过
（同一个 pid、同一个 Qt 窗口类），结果密文被粘进二维码窗口，**桥还报告 `ok`**。

现在发送前有三道闸，任一不过**一个按键都不发**：

1. 把微信切到前台
2. 前台窗口确实属于微信进程且 class 含 `Qt`
3. **窗口处于已登录状态**

第 3 条的判据（实测数据）：

| | 尺寸 | 可缩放 |
|---|---|---|
| 登录二维码界面 | 295×387 | ❌ 固定 |
| 已登录主界面 | 1017×690 / 1721×1041 | ✅ 有 WS_THICKFRAME |

调试端点：`GET /wincheck?hwnd=<十进制句柄>` 会对任意窗口跑一遍这个判据。

## 已知限制

- **⚠️ 粘贴目标取决于微信内部哪个输入框有焦点。**
  如果微信没打开任何对话、或焦点在「搜索」框，密文会粘到奇怪的地方。
  **发送前请确认微信里打开着目标对话。** 这一条桥分辨不了（UIA 读不到微信内部）。
- **多端不隔离**：桥是全局单例后端，多个标签页会互相看到消息。
- **只监听 `127.0.0.1`，无鉴权**：本机自用没问题。
- **公钥不持久化配对**：对方公钥只在当前页面会话里有效，刷新后要重新交换
  （私钥是持久化的，所以你的指纹不变）。
