🌉 桥

检查中…

桥是一个 20 KB 的小程序，用 Windows 自带的 C# 编译器现场编译。 不需要 Python / Node / .NET SDK，也不用联网下载任何东西。 它负责把密文写进剪贴板、切到微信、按 Ctrl+V Enter， 同时监听剪贴板，你在微信里 Ctrl+C 就能自动收。

存成 install-bridge.bat，双击运行即可，它会自己编译并启动。
首次运行 Windows 可能提示"已保护你的电脑"，点 更多信息 → 仍要运行（脚本文件的正常提示）。
「下载」走的是浏览器下载管道，而 .bat 属于危险文件类型， 可能被拦下挂起。拦住了就点 📋 手动保存 —— 那条路不用下载、不调文件选择器，任何环境都成立。

🔑 会话密钥

未就绪

点顶栏的「密钥」就是把公钥发出去。双方各点一次，就能各自算出同一个会话密钥。 私钥永远不出本机。

公钥以 E2E1-K.… 开头，会作为一条普通微信消息发出去 —— 别人看起来就是一串乱码。

桥直接从微信进程内存里读 SQLCipher 解密后的页： 不用密钥、不动鼠标、不占剪贴板、不改焦点。 中文原样显示，密文自动解密，取最近 5 条。
看得到的是页缓存里还有的页， 所以它的正确用法是"消息一到就去读" —— 刚写入的页必然还在缓存里。

📥 手动收下

把对面发来的那条 E2E1-K.… 整条粘进来点「收下」。 跟桥推过来走的是同一条接收路径（handleIncoming）。

为什么需要这个：页面自己读不到微信， 正常情况靠桥监听剪贴板把消息推进来。桥没跑、页面没连上、或者剪贴板那条链断了， 这里就是唯一能手动接上的入口。

🔗 会话 



  

    最近有动静的 3–5 个对话，每条拿它最新那条消息当身份
    （时间 + 对方 + 正文）。点一条就绑定，之后只读它、而且自己发的不再当收到的。
    点最上面那条「（自动）」= 解绑。点「🔄 刷新」重新识别一次最新的消息。
    
识别走两条路：会话行给出"最新消息的 local_id"，
    表名由对方 wxid 直接算出 Msg_<md5>；根页不在页缓存里时，
    就按 local_id 去内存页映像里认那一页。读不到正文的（公众号等）回落成会话摘要。

    点「测试连接」会现场生成第二把 ECDH 密钥当假对方，走真实的
    setPeerPub 协商。之后你发一条消息，页面会
    用它真的解一遍你的出站密文，再以对方的身份加密一条回复回来 ——
    一问一答，两个方向都跑到，不用等第二个人。
  

  

    密钥按公钥字典序切成两半，所以对方的发送键 = 我的接收键。
    两把钥匙本来就在这台机器上，回路用的是真 AES-GCM 和真计数器，不是模拟。

    要是已经跟真人交换过公钥，之后得重新交换。
