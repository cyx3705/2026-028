🌉 桥

检查中…

桥是一个 20 KB 的小程序，用 Windows 自带的 C# 编译器现场编译。 不需要 Python / Node / .NET SDK，也不用联网下载任何东西。 它负责把密文写进剪贴板、切到微信、按 Ctrl+V Enter， 同时监听剪贴板，你在微信里 Ctrl+C 就能自动收。

存成 install-bridge.bat，双击运行即可，它会自己编译并启动。
首次运行 Windows 可能提示"已保护你的电脑"，点 更多信息 → 仍要运行（脚本文件的正常提示）。
「下载」走的是浏览器下载管道，而 .bat 属于危险文件类型， 可能被拦下挂起。拦住了就点 📋 手动保存 —— 那条路不用下载、不调文件选择器，任何环境都成立。

🔑 会话密钥

未就绪

点顶栏的「密钥」就是把公钥发出去。双方各点一次，就能各自算出同一个会话密钥。 私钥永远不出本机。

公钥以 E2E1-K.… 开头，会作为一条普通微信消息发出去 —— 别人看起来就是一串乱码。

桥会自动切到微信 → 在消息区拖选可见消息 → Ctrl+C 复制回来。 中文原样显示，密文自动解密，取最近 5 条。
代价：这一下会切走焦点并占用剪贴板。 只拉当前对话里看得见的消息。

📥 手动收下

把对面发来的那条 E2E1-K.… 整条粘进来点「收下」。 跟桥推过来走的是同一条接收路径（handleIncoming）。

为什么需要这个：页面自己读不到微信， 正常情况靠桥监听剪贴板把消息推进来。桥没跑、页面没连上、或者剪贴板那条链断了， 这里就是唯一能手动接上的入口。

🧪 测试（假装第二端）

未启用

点「测试连接」会现场生成第二把 ECDH 密钥当假对方，走真实的 setPeerPub 协商。之后你发一条消息，页面会 用它真的解一遍你的出站密文，再以对方的身份加密一条回复回来 —— 一问一答，两个方向都跑到，不用等第二个人。

密钥按公钥字典序切成两半，所以对方的发送键 = 我的接收键。 两把钥匙本来就在这台机器上，回路用的是真 AES-GCM 和真计数器，不是模拟。

勾上就走真桥发到微信当前打开的那个对话 （你现在停在哪个聊天，就发到哪个）—— 微信里会看到一问一答两条密文， 页面上看到对应的两条明文。发之前确认一下微信停在对的对话上。
测试连接会顶掉当前会话密钥 —— 要是已经跟真人交换过公钥，之后得重新交换。

📥 反向测试：我当接收方

模拟对方把公钥发过来，你站在接收端看状态怎么变。 这三步走的是真实的接收路径（handleIncoming）， 不是绕过它直接调 setPeerPub。

预期：清空后密钥药丸变黄、输入框禁用； 收下对方的公钥后变绿、输入框启用、显示指纹； 收下自己的公钥应该被拒绝（"这是你自己的公钥，忽略"）。

还没装桥 —— 装好后页面会自动连上 （也可以点右上角的「桥」看详细说明）

📋 手动保存安装脚本 —— 任何环境都能用

  1. 脚本已经生成在下面的文本框里，点一下文本框会自动全选（或按 Ctrl+A）
  2. 按 Ctrl+C 复制
  3. 打开记事本，按 Ctrl+V 粘贴
  4. 文件 → 另存为：文件名填 "install-bridge.bat" —— 要带引号，这样记事本才不会偷偷加 .txt； 保存类型选「所有文件」，编码选 ANSI
  5. 双击运行 install-bridge.bat
